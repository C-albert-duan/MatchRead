02  ·  Direction

One trust boundary, not eight bugs

A wrong-tour player, a stalled quarter, a truncated surname, a universal Hard default and a tournament still marked Open ten days after play began are not five defects. They are five places where provider data crossed into MatchRead without being checked, and where the system chose a plausible value over an honest failure.

The fix is not more careful ingestion. It is an ingestion layer that refuses to publish what it cannot verify, repairs itself on a schedule, and reports its own failures before a consumer finds them. Every section below is an instance of that.

4.1 Cross-cutting rules that override anything below

These are house rules this repository already enforces. They are restated here because a playbook that omits them invites a well-meaning engineer to break one under time pressure.

RuleDetail
Service role The service-role key exists only in edge functions and the settlement worker. Server components authenticate as the user via @supabase/ssr. Using it in a server component silently discards every RLS policy in 0001 and 0004 and fails open — nothing breaks and nobody notices until someone reads another user's unlocked bracket. Enforced by lint and a CI grep; the admin integrity page in §4 is the single most likely place for this to be broken this sprint.
RLS Every table a user can read is covered, no exceptions. New tables and new columns on existing tables inherit that obligation. An integrity or audit table is not exempt because it is internal.
pgTAP Every acceptance test in this document names a file under supabase/tests/. A test described in prose and not written is a defect that will recur. Never apply anything in supabase/tests/ to a real project — one file recreates auth.users.
Lock authority A Postgres trigger, migration 0013. If you find yourself adding a lock rule to a component, it belongs in the database or in packages/core.
No silent defaults Unknown provider enum values are logged and alerted, never coerced. This rule applies to the migrations in this document as much as to the provider — v1.0 broke it in its own identity migration, which is why §6 is rewritten.
Idempotency Provider payloads must be replayable without double-settling. Out-of-order and duplicate delivery are normal, not exceptional.
Copy is i18n Three locales ship: en, es, ja. Every new user-visible string in this sprint — empty states, integrity warnings, the "no draw open" message in §13 — needs all three or it renders as a key.
One definition UI components never encode tier eligibility, tour mapping or tournament-state rules. If a rule appears in a component, it has already been duplicated.
05  ·  P0-1  ·  Green by 24 Aug

Product scope: ATP and WTA 250+

A tournament is publicly bracket-eligible only when it is ATP or WTA and its level is 250 or above. Grand Slams and Tour Finals are in. Challenger, ITF and WTA 125 events may continue to be ingested for coverage; they are not public bracket products unless explicitly flagged on.

The live calendar currently lists roughly 250 events, of which the great majority are M15, M25, W15 and W35. The homepage promises "Fill a bracket" and lands on a list whose first thirty-six rows are on-court events nobody can enter. Narrowing is a product improvement in its own right — but it is first on this list because of what it does to risk: it removes most of the rows the reconciliation job must keep fresh, and it removes the exact draws where the worst defects live.

5.1 Reconcile with the existing enum. Do not create a second one.

Migration 0001 already defines tournament_tier as ('grand_slam','tour_finals','masters_1000','tour_500','tour_250','other'), and it is wired into the rating K-factor per ADR-0003. v1.0 proposed a parallel TournamentLevel vocabulary. Two level vocabularies is precisely the duplication §4.1 forbids, and the proposed one silently dropped tour_finals.

Extend the enum instead. The three numeric tiers are level names, not tour names — tour is a separate column and already disambiguates a WTA 1000 from an ATP Masters 1000. What is missing is the ability to say what an event is when it is below 250, because other is currently a dumping ground that cannot be filtered on.

-- 0029_tournament_levels.sql
-- Postgres will not let a new enum value be used in the same transaction that
-- adds it, and Supabase wraps each migration in one. This migration adds the
-- values and nothing else; 0030 backfills. Do not merge them.

alter type tournament_tier add value if not exists 'challenger';
alter type tournament_tier add value if not exists 'wta_125';
alter type tournament_tier add value if not exists 'itf';

-- comment on the three numeric tiers so the next reader does not repeat
-- v1.0's mistake and assume masters_1000 is ATP-only.
comment on type tournament_tier is
  'Level, not tour. masters_1000 covers ATP Masters 1000 and WTA 1000; '
  'tour_500 and tour_250 cover both tours at those levels. Disambiguate '
  'with tournaments.tour. Levels below 250 are named explicitly so they '
  'can be excluded from the public bracket product rather than hidden '
  'inside ''other''.';
-- 0030_bracket_eligibility.sql

create type product_override as enum ('force_on','force_off');

alter table tournaments
  add column product_override product_override,          -- null = policy decides
  add column ingestion_enabled boolean not null default true,
  add column featured boolean not null default false;

-- One authoritative definition, in SQL, so the public query can use it.
-- packages/core mirrors it for the TypeScript side and 23_eligibility.test.sql
-- asserts the two agree.
create or replace function is_bracket_product(
  p_tour tour,
  p_tier tournament_tier,
  p_override product_override default null
) returns boolean
language sql immutable as $$
  select case
    when p_override = 'force_on'  then true
    when p_override = 'force_off' then false
    else p_tier in ('grand_slam','tour_finals','masters_1000','tour_500','tour_250')
  end
$$;

-- Stored, so the calendar query is an index scan rather than a function call
-- per row. Generated, so it cannot drift from the policy.
alter table tournaments
  add column bracket_eligible boolean
  generated always as (is_bracket_product(tour, tier, product_override)) stored;

create index tournaments_public_calendar
  on tournaments (starts_on)
  where bracket_eligible;
Rule

Call is_bracket_product() — or read bracket_eligible — at ingestion activation, public calendar queries, bracket creation, tournament landing CTAs and admin QA. Level rules never appear in a React component. Keep ingestion_enabled and featured independent of eligibility: MatchRead can ingest what it does not merchandise, and can support every 250+ event while the homepage leads with ten.

5.2 Backfill, and the question v1.0 did not answer

Roughly 250 tournament rows are already ingested with tier almost certainly set to other, and some number of brackets may already exist against them. Narrowing the product must not destroy user data.

  • Backfill tier from the provider category field, not from the name string. Where the provider gives no category, leave the row and alert; do not guess from M15 in the title. Guessing from names is the defect in §8 wearing a different hat.
  • Ineligible does not mean deleted. An existing bracket on a now-ineligible tournament stays readable, stays in its league, and settles normally. Eligibility governs discovery and new entry, nothing else. Assert this: it is the rule most likely to be broken by a well-meaning cascade.
  • Nothing new may be created on an ineligible tournament. Enforce in the database, not the route — a check constraint or a policy on brackets, so a stale client cannot get around it.
  • force_off is the incident kill switch. A tournament whose data has gone wrong mid-event is pulled from the public product with one update, without a deploy and without touching bracket rows. Document it as the on-call action.

5.3 Acceptance — supabase/tests/23_eligibility.test.sql

  • Seed one ATP 250, one ATP Challenger, one WTA 250, one WTA 125, one ATP 1000, one Grand Slam and one ITF M15. Public bracket discovery returns exactly the four 250+ rows; all seven remain present for internal ingestion.
  • force_on promotes the Challenger; force_off demotes the Grand Slam. Both are reversible and neither touches bracket rows.
  • A bracket created before demotion survives it, remains readable by its owner and its league, and still settles.
  • Inserting a new bracket against an ineligible tournament is rejected by the database.
  • The tier list inside is_bracket_product() equals PUBLIC_TIERS exported from packages/core, fed in as a fixture. This assertion is the thing that stops the two definitions drifting.

Tournament and tour identity

The ATP M15 Tianjin draw contains several feminine surname forms, and a W15 Tianjin exists in the same week. That is a cross-tour contamination signal. Do not delete the row. Trace the provider tournament ID, season ID, draw ID, tour discriminator and player IDs through the whole ingest path, and make the wrong result impossible rather than absent.

6.1 Hypotheses to falsify, in order of likelihood

  • Provider tournament IDs are unique only within a tour namespace, and MatchRead treats them as globally unique.
  • A season-to-tournament join uses the provider ID without also checking tour.
  • ATP and WTA events with matching city or name strings are being merged by a slug fallback. Masters event, 32-draw event and the slam event all have this shape, so this hypothesis is testable against events that matter.
  • Draw import selects the wrong season_id, or reuses a cached response from the previous tournament in the loop.
  • Normalization permits an existing tournament row to be updated from a payload belonging to another tour.
Corrections to v1.0

v1.0's migration added provider text not null default 'matchstat' — a silent default, in a NOT NULL column, naming a provider the integration brief does not mention. That is the same defect class as the universal Hard surface, shipped inside the migration meant to fix it. It also added tour text, which shadows the existing tour enum from migration 0001. Both are removed below.

6.2 Runtime invariant

Placed in packages/core/src/ingest/ so the edge function, the reconciliation job and the verification CLI all use the same one.

export function assertDrawBelongsToTournament(
  draw: NormalizedDraw,
  tournament: TournamentRow,
): void {
  invariant(draw.providerTournamentId === tournament.providerTournamentId,
    `provider tournament mismatch: ${draw.providerTournamentId}`);
  invariant(draw.providerSeasonId === tournament.providerSeasonId,
    `provider season mismatch: ${draw.providerSeasonId}`);
  invariant(normalizeTour(draw.tour) === tournament.tour,
    `tour mismatch: draw ${draw.tour} into ${tournament.tour} tournament`);
}

Failure is loud and the payload is not persisted. A rejected import is an alert and a DRAW_PENDING tournament; a silently accepted one is a bracket with the wrong people in it, which nobody notices until a user does.

07  ·  P0-3  ·  Green by 24 Aug

Result reconciliation and exceptional outcomes

A single unrecorded Masters event R32 result — Fonseca against O'Connell on 18 August — left the R16 reading "Not played" and a quarter-final with an empty seat, while every other quarter advanced to the last eight. Matches played later the same day settled correctly, so this is not lag. It is one fixture that never came back, and nothing swept up behind it. It is still wrong today.

Live feeds drop events. That is not a provider defect to be complained about, it is a property of the medium. The design answer is an authoritative periodic sweep whose job is to assume the stream lied and prove it — the reconciliation layer the integration brief already names as the backstop behind both pipelines.

7.1 The loop

  1. Select tournaments that are bracket_eligible and not COMPLETE, plus any explicitly monitored.
  2. Fetch the provider's authoritative completed and current fixture set for each.
  3. Compare provider status and winner against stored fixture state.
  4. Upsert changed fixture facts idempotently, keyed on the provider fixture ID.
  5. For each newly resolved winner, invoke the existing settlement path. Do not reimplement advancement.
  6. Recompute downstream participants only from stable upstream winner IDs, never from a seat's current label.
  7. Log every repair: tournament ID, fixture ID, before, after, source timestamp, job run ID.
  8. Alert when a provider fixture is terminal but cannot produce exactly one valid bracket winner.
export async function reconcileTournament(tournamentId: TournamentId) {
  const run = await audit.startRun('reconcile', tournamentId);
  const tournament = await repo.getTournament(tournamentId);
  const providerFixtures = await provider.getTournamentFixtures(tournament);

  for (const raw of providerFixtures) {
    const normalized = normalizeFixture(raw);           // packages/core/src/ingest
    const current = await repo.getFixtureByProviderId(normalized.providerId);
    if (!needsRepair(current, normalized)) continue;

    const repaired = await repo.upsertFixture(normalized);
    if (canAdvanceWinner(repaired.outcome, repaired.winnerPlayerId)) {
      await settleDraw({ tournamentId, fixtureId: repaired.id, runId: run.id });
    }
    await audit.logRepair({ runId: run.id, before: current, after: repaired });
  }

  await repo.setTournamentState(tournamentId, deriveTournamentState(tournament)); // §11
  await audit.finishRun(run.id);
}

7.2 Terminal outcomes are explicit

type MatchOutcome =
  | 'COMPLETED' | 'WALKOVER' | 'RETIREMENT'
  | 'DEFAULT'   | 'CANCELLED' | 'SUSPENDED';

const ADVANCING: ReadonlySet<MatchOutcome> =
  new Set(['COMPLETED', 'WALKOVER', 'RETIREMENT', 'DEFAULT']);

export function canAdvanceWinner(outcome: MatchOutcome, winnerId?: string) {
  return ADVANCING.has(outcome) && Boolean(winnerId);
}
Never infer a winner from score text

The provider's winner or player ID is authoritative. Scores are presentation data and are routinely incomplete for walkovers, retirements and defaults — which are exactly the cases where inference is most tempting and most wrong.

7.3 The gap this exposes, which v1.0 normalized but did not solve

SUSPENDED and CANCELLED normalize cleanly and then have nowhere to go. Per ENGINEER-MAPPING.md, postponed, suspended and cancelled have no first-class representation in the tournament UI at all. Geneva 2025 is the only tournament ever replayed against this system and it contained no retirements, walkovers, withdrawals or suspensions, so the entire disruption pipeline has never met real data.

Two consequences for this sprint. First, normalizing an outcome the product cannot display is half a fix: budget UI for the three states, even if it is one honest sentence per state. Second, withdrawal and replacement already have semantics — migration 0028 defines voided picks, which are neither correct nor incorrect and get neither green nor red. Use them. Do not invent a second representation of the same idea.

7.4 Cadence, measured rather than inherited

v1.0 proposed "every 2–5 minutes if quota permits." That is the same number runbooks/SETTLEMENT-SCHEDULING.md describes, in its own words, as a guess informed by nothing — and ADR-0018 asks for it to be set from provider quota instead. The Geneva capture has the data to do that.

7.5 Acceptance — supabase/tests/25_reconciliation.test.sql and packages/settlement/src/reconcile.test.ts

  • Replay the Masters event draw with the Fonseca–O'Connell result withheld, then supply it. The R16 and QF seats resolve without manual intervention and without double-settling anything downstream.
  • The same payload delivered twice produces one settlement. Out-of-order delivery produces the same final state as in-order.
  • A terminal fixture with no winner raises an alert and advances nothing.
  • A walkover with no score text advances the winner.
  • A retirement mid-match advances the winner and preserves the partial score for display.

Player identity and display names

Masters event renders Aliassime, Minaur, Zandschulp, Assche and Jong — particles stripped from Auger-Aliassime, de Minaur, van de Zandschulp, van Assche and de Jong. Tianjin renders Mingzhou and Hongyu, which are given names, so for Chinese players the parser is taking the wrong end of the string entirely. And Tianjin's R64 puts Gao next to Gao, Han next to Han, and three players labelled Chen in the same draw.

This is the defect a user meets first, and it is the one that makes the product look scraped. It is also worse than cosmetic: a bracket with two identical seats cannot be filled. There is no pick to make when both options read the same.

8.1 Separate identity from display

type Player = {
  id: PlayerId;                  // MatchRead internal UUID
  provider: DataProvider;
  providerPlayerId: string;      // the identity key. the only join key.
  displayName: string;           // provider canonical, user-facing
  firstName?: string | null;     // auxiliary. never a join key.
  lastName?: string | null;      // auxiliary. never a join key.
  countryCode?: string | null;
};
  • Never create or join a player by name. Section 07 of the integration brief says this in as many words; the display layer has the same problem the matching logic was warned about.
  • Never derive a display name by taking the last token. Preserve particles, hyphens, accents, multiword surnames and cultural name order.
  • If the provider gives no clean display name, use an explicit formatter with country and language awareness — and treat it as a fallback that is logged, not a normal path.
  • Existing players.last_name stays as an auxiliary column. It is not deleted and it is not trusted.

8.2 Backfill

  1. Add display_name and provider_player_id if absent.
  2. Backfill from the provider canonical name for every player referenced by an active bracket_eligible draw. That set is small once §5 lands — this is the second time narrowing scope pays for itself.
  3. Flag unresolved or suspicious names rather than guessing. A flagged seat blocks publication (§16); it does not get a plausible label.
  4. Rebuild any search index that depends on name parts — players_name_trgm in migration 0001 indexes full_name and must follow the new canonical value.

8.3 Duplicate-label detection

-- Run per draw, not globally. Duplicate labels across the season are fine;
-- duplicate labels inside one bracket are the defect.
select d.tournament_id, p.display_name, count(*) as seats
from draw_seats s
join draws   d on d.id = s.draw_id

The QA rule

Duplicate display names are legitimate — two Cerundolos really are in the Masters event draw. The rule is not "duplicates forbidden," it is "duplicates must remain distinguishable" through seed, country, full canonical name or another stable visible discriminator. In a seeded draw, seed and country usually do it. In an unseeded ITF draw with two Chinese players named Gao and the same flag, they do not — which is one more reason those draws are not a public bracket product.

8.4 Land the fix once

Per ENGINEER-MAPPING.md, the seed / name / country triple is hand-rolled in four places: the bracket editor, the rankings table, the operator seat list and the draw list. Extracting PlayerChip is already recorded in KNOWN_WEAKNESSES and the spec prototype implements it once. Do that extraction as part of this fix, so the disambiguation rule exists in one component rather than being reimplemented four times and drifting three ways.

8.5 Acceptance — supabase/tests/26_player_display.test.sql and packages/core/src/ingest/name.test.ts

  • Fixtures covering, at minimum: a particle surname (de Minaur), a compound particle (van de Zandschulp), a hyphenated surname (Auger-Aliassime), a family-name-first order (Chinese and Japanese entrants), an accented surname, and a two-word surname without a particle (Carreño Busta). Each round-trips to the provider canonical form.
  • No player in an eligible draw has a display_name produced by the fallback formatter without a corresponding log line.
  • The duplicate-label query returns no row for any eligible draw where the duplicates lack a visible discriminator.
  • Renaming a player upstream does not create a second player row.

Surface and environment

Every one of the roughly 250 tournaments on the live calendar is labelled Hard, including events at Todi, Lesa, Santa Margherita di Pula and Campos do Jordão. The calendar offers four surface filters and three of them return nothing. Every page in the product shares one Open Graph image, court-hard.webp.

surface is not null in migration 0001, and the provider exposes the value as court on the calendar endpoint. Something is filling the column rather than mapping it. Remove the fallback.

export function normalizeSurface(raw: string | null): Surface | null {
  const v = raw?.trim().toLowerCase();
  if (!v) return null;                          // unknown is a value, not an error
  if (v.includes('clay'))   return 'clay';
  if (v.includes('grass'))  return 'grass';
  if (v.includes('carpet')) return 'carpet';
  if (v.includes('hard'))   return 'hard';
  throw new UnknownProviderValue('surface', raw);  // logged, alerted, never coerced
}

export function normalizeEnvironment(raw: string | null): Environment | null {
  // Separate axis. "Indoor Hard" is two facts, not one.
}
Three consequences the schema forces

Indoor is not a surface. The enum is hard | clay | grass | carpet; the calendar's fourth filter chip says Indoor, which is an environment. Either the filter is rebuilt on two axes or the chip is removed — it cannot stay as it is. Unknown must be representable. That means dropping the not null on surface so an unmapped value is visible to admin QA rather than silently rewritten to Hard. Only expose filters the data supports. A filter that returns nothing teaches a user the product is empty.

The court hairline is the one place these values become visible. Four colours, three pixels, on a tournament row and nowhere else — enough to make the shape of a tennis year legible without a word of explanation. Getting the mapping right is what earns that.

Tournament-state reconciliation

W75 Kursumlijska Banja, starting 10 August, is still listed as open for entry today, ten days later — while the 17 August edition of the same event shows On court. Events whose results never ingested never transitioned. This is a symptom of §7 rather than an independent bug, and it mostly disappears when reconciliation runs. 

type TournamentState =
  | 'DRAW_PENDING' | 'OPEN' | 'LOCKED' | 'ON_COURT' | 'COMPLETE';

export function deriveTournamentState(ctx: StateContext): TournamentState {
  if (ctx.allMatchesTerminal) return 'COMPLETE';
  if (ctx.anyMatchStarted)    return 'ON_COURT';
  if (ctx.now >= ctx.locksAt) return 'LOCKED';
  if (ctx.drawPublished)      return 'OPEN';
  return 'DRAW_PENDING';
}
This function is presentational

It decides what badge to draw. It is not a lock. Lock is enforced by a Postgres trigger in migration 0013, and bracket submission must be refused by that authoritative clock even when a stale badge still says Open. Two clocks is worse than one wrong badge: a badge is a cosmetic defect, a second clock is a bracket edited after the first ball.

  • Persist the derived state if it helps queries, but treat it as repairable cache, never as truth.
  • Recompute after every provider update and on the reconciliation schedule.
  • A tournament that has been OPEN past its own start date for more than one sweep is an alert, not a display quirk. That single assertion would have caught this defect ten days ago.
12  ·  P1-8  ·  Green by 31 Aug

Peak load and incident response

Absent from v1.0 and specific to this launch. The slam event traffic profile is not a ramp, it is a cliff: the last three hours before lock, when everyone who procrastinated fills 127 slots each, simultaneously.

  • Load-test that shape, not an average day. The relevant metric is concurrent whole-bracket submissions in the final hour, not requests per second across a week.
  • Entry is already incremental and resumable, which is what stops a dropped connection at 10:47 costing twenty minutes of work. Do not regress it while touching the seat components in §8.
  • The bracket editor renders every round in full. Fine at 32 seats; a 128 draw is a very tall column. Mobile solved this with a quarter-and-half DrawNavigator — that component is the model to port, and the slam event is the first 128 draw the web tier will ever serve.
  • Incident response is product_override = 'force_off' (§5). One update pulls a tournament whose data has gone wrong out of the public product, with no deploy and no data loss. Write it into the on-call notes with the exact statement to run.
  • Every repair is logged with a run ID, so the question "why is this bracket wrong?" is answered from the audit trail rather than by reading random rows at 3am.

Timezone presentation

Masters event fixtures display at 01:45, 02:10 and 05:35 in the morning. They read correctly as UTC and nonsensically as anything else. Store UTC; convert only at the presentation boundary; decide once whether MatchRead shows viewer-local time, tournament-local time, or both.

Constraint v1.0 omitted, and the reason this is not a five-minute fix

Format on the server, against an explicit zone. The BetweenTournaments work already does this deliberately: rendering a time on the client flashes on first paint and produces a hydration mismatch that React resolves by trusting the server — so the correction sometimes never happens. A client-side Intl.DateTimeFormat reintroduces a bug this codebase has already solved.

  • Persist starts_at as timestamptz.
  • Persist the tournament's IANA zone — America/New_York for 64-draw event and the slam event — as a column, not a lookup.
  • Prefer preferences.time_zone where the viewer has one; otherwise tournament-local, which is always safer than raw UTC.
  • Label it when ambiguity matters. The lock deadline in particular already has a LocalDeadline primitive; every other displayed time should match its behaviour.

The 64-draw event readiness gate

Success is not "the page loads." Success is an ATP 250 that imports, opens, locks, reconciles, settles and completes without a single manual database intervention. Every hand-run SQL statement during the rehearsal is a defect that will recur at the slam event with a hundred times the audience.

Before draw publish Normalized as ATP, tier tour_250, bracket_eligible true. Provider and season IDs composite-unique. Surface and IANA zone mapped from provider values, not defaults. Verification CLI returns SAFE_TO_PUBLISH=true.

Completion Champion and standings settle. State becomes COMPLETE. Final repair sweep passes. previous_score is non-null and the Daily Check has something to say.

19  ·  Handoff

Definition of done, and the posture that gets you there

  • No manual SQL correction is required to complete a normal 250-level tournament lifecycle.
  • Every ingestion assumption that matters to bracket correctness has an automated assertion or a verification probe.
  • Provider payloads can be replayed without double-settling or corrupting downstream state.
  • Public bracket discovery is intentionally limited to ATP and WTA 250+ products, and the limit is enforced in one place.
  • An engineer can answer "why is this bracket wrong?" from logs and audit data, without inspecting random database rows.
  • 64-draw event has been run end to end as a rehearsal, and every intervention it required has become a test.

19.1 Posture

Prefer invariants, idempotent repair and explicit failure over silent fallback. The live site has already demonstrated the failure mode this sprint exists to end: ingestion that is mostly correct looks convincing, ships, and breaks the experience anyway.

Do notBecause
Rewrite the bracket engine Unless a failing test proves the engine itself is wrong. Every piece of evidence here points at source normalization and missing reconciliation.
Fix a production example by hand and close the defect Convert every production failure into a regression test or an integrity rule. The Masters event quarter-final can be repaired with one UPDATE; doing that and stopping is how it happens again at the slam event.
Match tournaments or players by name Provider IDs exist. Name matching is the root of both the tour-contamination signal and the duplicate-seat defect.
Let a component encode a rule Tier eligibility, tour mapping and state rules live in one place each. A rule in a component has already been duplicated.
Swallow an unknown provider value Log and alert. An unknown surface is information; a defaulted one is a lie the product tells on 250 pages.
Reach for the service-role key It fails open, so nothing breaks and nobody notices. Of everything in this document, this is the mistake with the longest gap between committing it and discovering it.
Add a second lock The trigger in 0013 is the clock. Anything else is a UI hint.
Ship a new string in one language Three locales, or it renders as a key.
